# v2 ドッグフーディング記録(2026-10-21)

v2 を本番オペレーターが使う順番で一通り操作した記録。以前は v2 に画面を外から操作する手段が無く、
起動確認とテストまでしか見られなかったため、まず自動操作の口をアプリに入れ(後述)、そのうえで
v3 と同じシナリオを流した。入力はダイアログへの手入力、結果は画面(スクリーンショット)・ViewModel の状態・
OSC 受信側(`tools/tcb3/osc_listen.py` をポート 9100 で起動)の 3 点で確認した。

## 使った環境

- v2: `feature/macos-app` を `dotnet` で起動。ポート 47201、設定の保存先は専用ディレクトリに隔離。
- LTC: 同一プロセスの自己テスト信号(Pro Tools Audio Bridge 2-A のループバック)。
- OSC 送信先: 「QLab 本番」127.0.0.1:9100(受信側あり)と「照明卓」192.0.2.1:53000(到達不可)。

## 入れた仕組み

アプリ内に、環境変数があるときだけ起動する HTTP の受け口を置いた(`Services/Automation/`)。
外から状態の取得、ビジュアルツリーの列挙、クリック・入力・キー送信、ウィンドウの撮影、
ViewModel コマンドの実行ができる。操作用の CLI は `tools/tcb2/tcb2ctl`。

撮影はアプリ内で描画するので、OS の画面収録権限が要らない。これが無かったために前回は v2 の画面を
一切見られなかった。あわせて設定の保存先を差し替える環境変数を足し、試験用インスタンスが
利用者の `settings.json` を汚さないようにした。

使ううえでの注意が一つある。**モーダルダイアログが開いている間は UI スレッドが止まる**ので、
完了を待つ指定での入力・クリックは時間切れになる。先にウィンドウ一覧を見てダイアログを閉じること。

## 見つけた不具合(修正済み)

### Cue-Sync の送信先チェックが 1 回遅れていた

チェックした直後に CUE SYNC を押しても送られず、次に何か操作したときに前の状態が反映される。
本番でホストを選び直した直後に押すと無音になる、実害のある挙動だった。

画面側のチェック変更イベントがデータの反映より先に走り、古い選択を読んでいたのが原因。
画面のイベントに頼るのをやめ、選択状態の変更そのものを ViewModel 側で購読するようにした。
退行を防ぐテストを 2 件足している。

### 連続複製の初期値が「複製数 23・間隔 1 時間」だった

秒だけ直して実行すると、1 時間刻みのキューが 23 件増える。「複製数 1・間隔 0」に変え、
間隔を入れずに実行すれば既存の検証で止まるようにした。

## 使っていて引っかかった点(未修正・提案)

1. **数値欄に不正な文字を打つと黙って最小値に落ちる。** 判定幅は 0 になり、ジャンプ判定が無効化されて
   頭出しや巻き戻しでも途中のキューが発火しうる。ポン出しの行・列は 1 になる。打った文字は消えて
   最小値が表示されるだけなので、操作者は値が変わったことに気づけない。
2. **オフセット欄に不正な文字列を入れると、その文字が欄に残り続ける。** 内部のオフセットは変わっていないのに
   画面には残るので、本番前に「オフセットが入っている」と誤読する。コード上は実値へ戻す意図だが戻っていない。
3. **OSC 引数の書式が v2 と v3 で違う。** v2 は `i:1 f:0.5 s:intro`(空白区切り・型は i/f/s)、
   v3 は `int32:1`(1 行 1 件)。v3 の書式を入れると入力エラーになる。黙って捨てないのは良いが、
   版をまたぐ利用者は引っかかる。
4. **フレーム数の上限エラーに実際の上限値が書かれていない。** 30fps で 35 と入れると
   「FF(0-max)」と出るだけ。v3 は入力時に 29 へ丸めて範囲を表示する。
5. **Cue-Sync の送信先が 0 件のとき、押しても何も起きず表示も出ない。** v3 は送信先を選ぶよう案内が出る。
6. **起動直後に入力デバイスを選んだだけでプロジェクトが未保存扱いになる。** そのままプロジェクトを開こうとすると
   破棄の確認が出る。デバイス選択がプロジェクトの一部であるため。v3 はアプリ設定なのでプロジェクトは汚れない。

## 画面の見た目で気になった点

1600px 幅で確認した範囲。

- 入力デバイスの行で、フレームレートのラベルと選択欄が「再接続」ボタンと重なって読めない。
- 再接続とデバイス更新の記号が字形を持たず豆腐になる。
- LTC のラジオボタンの文字が右端で欠ける。
- ログに出るホスト名が本文と別のフォントで小さく上にずれる(等幅フォントに和文が無いため)。
- Cue-Sync の送信先一覧は 1 行分しか見えず、2 件目以降はスクロールが要る。

## 確認して問題なかった操作

- **ホスト管理**: 名前・IP・ポート・有効を入力して登録。疎通確認は到達可で RTT 表示、到達不可は
  約 3 秒後に失敗がログに残る。
- **キュー編集**: ダイアログ手入力で追加(型つき引数も保存)、選択して編集、複数選択しての一括編集
  (OSC アドレスをまとめて変更)、時間順の並べ替え、削除確認、Cmd+Z での取り消しとやり直し。
  削除の確認には消える対象の時刻と名前が並ぶ。
- **プロジェクト**: 保存 → 新規 → 再オープンでキュー・ホスト・ポン出しが戻る。最近使ったプロジェクトにも入る。
- **本番走行(LTC 受信)**: キューが時刻どおり発火して OSC が届く。発火時ミュートを付けたキューは
  発火と同時にミュートされ、行に解除までの残り時間が出て、指定時間後に自動で復帰する。
  手動ミュート中のキューは発火しない。次のキューまでの残りは時間表記で出る。
- **ポン出し**: 編集モードで空セルから作成し、実行モードで押すと OSC が届く。Esc で編集モードに戻る。
  行・列を減らすとき消えるボタンがあれば確認が出て、取り消せば行数・表示・ボタンがすべて元に戻る。
- **内部生成**: 開始時間を入れて再生すると走り出し、その時刻のキューが発火して OSC が届く。
  停止・リセットのあと LTC 受信に戻ると再び受信する。
- **ログ**: 失敗のみの絞り込みとクリアが効く。

## 補足

MUTE 中に見送ったキューがログに残らない点は v2・v3 共通で、本番後に「なぜ出なかったか」を追えない。
v3 側の記録にも同じ指摘を残してある。
