# UI レイアウト破綻の洗い出し(2026-10-21)

画面が崩れていないかを、目視ではなく実測で確かめた記録。`tools/tcb3/layout-check.js` を
動作中のアプリに流し込み、場面を一通り作りながら検査した。

## 検査するもの

- **画面外へのはみ出し**: 要素が画面の右・左・下を越えていないか
- **枠からあふれた文字**: 器より長い文字列が、省略記号なしで切られていないか
- **操作要素どうしの重なり**: 同じ層にあるボタンや入力欄が重なっていないか
  (ドロワーやダイアログのように手前へ重ねる設計の層と背後の要素は対象外)
- **潰れた操作要素**: クリックできないほど小さくなっていないか

入力欄は中身をスクロールして読むものなので、枠より長い値が入っていても破綻として扱わない。

使い方:

```
tools/tcb3/tcb3ctl eval "$(cat tools/tcb3/layout-check.js)" | jq .
```

## 見つけた破綻(修正済み)

### 長いホスト名が枠を越えて隣の表示に重なっていた

現場名と機材名を併記したような名前を登録すると、Cue-Sync の送信先一覧で名前が枠を越えて
描画され、隣の「n / m 有効」に重なっていた。実測で 211px はみ出し。

チェックボックスの label が横並び配置のため、名前をその直下に置くと省略指定が効かない。
名前を一段包むことで省略が効くようにした。キュー編集・一括編集・ポン出しボタンの
各ダイアログも同じ書き方だったので、あわせて直している。

### 一括編集の送信先ホストが横に流れて読めなくなっていた

一括編集だけチェックボックスを横に並べていたため、長い名前が入ると行の途中で折り返し、
どの名前がどのチェックボックスのものか判別できなくなっていた。キュー編集と同じ縦並びに揃えた。

## 検査して問題がなかった場面

通常画面、空のプロジェクト、キュー 20 件、1 件選択と複数選択、キュー追加ダイアログ
(ホスト 0 件と長い名前 3 件の両方)、ホスト追加・編集ダイアログ、一括編集、連続複製、
削除確認、ポン出しパネル(編集モード・実行モード・ボタン作成ダイアログ)、トースト表示中、
MUTE 状態、内部生成モード、送信ログが埋まった状態、ホスト管理タブ。

境界として、キュー名 120 文字・OSC アドレス 200 文字相当の極端な値も入れたが、
行は崩れず省略記号で収まった。

## 誤検出だったもの(検査スクリプト側を調整)

- **ポン出しパネルと背後の要素の重なり**: パネルは手前へ重ねる設計で、実際に背後の要素は
  パネル外では正常に操作できる。同じ層にある要素どうしだけを見るようにした。
- **閉じたドロワーの画面外配置**: 閉じている間は画面外に置くのが設計。対象から外した。
- **入力欄の文字あふれ**: 上記のとおり破綻ではない。対象から外した。

## 確かめていないこと

ウィンドウ幅を変えた場合の検証はしていない。画面は最小幅 1100px が指定されており、
1250px 以下で列幅を切り替える指定もあるが、今回は実ウィンドウ(1600x900)での検査に留めた。
