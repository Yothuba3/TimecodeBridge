# v1 のプロジェクトファイルを v3 で開けるか(2026-10-21 確認)

結論: **そのまま開けます。** 変換も互換レイヤーも要りません。

## 確かめ方

推測ではなく、両方の実物のコードを通して往復させました。

1. v1(`release/v1.4.13`)のモデルとシリアライザをそのまま取り出してコンパイルし、v1 の保存処理と同じ経路で
   プロジェクトファイルを書き出す。ドロップフレーム、負のオフセット、トリガーオフセット、発火時ミュート、
   型つきの OSC 引数(int32 / float32 / string)、追加アドレス、無効なホスト、ポン出しボタン、リレー設定を含めた。
2. そのファイルを v3 の `ProjectService.LoadProject` で読む。
3. さらに v3 の実アプリ(リリース版 .app)で `project.open` し、画面に出た内容を確認する。

いずれも全項目が欠けも化けもなく復元されました。

## なぜ開けるのか

ファイル形式に関わるモデルが v1 と v3 で同一のまま引き継がれているためです。

- 上位の項目構成(`cues` / `hosts` / `relaySettings` / `offset` / `sourceSettings` / `oscTriggerPanel` /
  `cueSync` / `cueAutoMuteEnabled`)が一致
- 入れ子のクラス(`Cue` `OscHost` `TimecodeValue` `TimecodeOffset` `OscTriggerButton` ほか)の
  プロパティ名と型が一致
- 列挙型(`FrameRate` `RelayIntervalMode` `TimecodeSourceType`)は数値で保存されるため、**定義順の一致が条件**になる。
  現状は一致している。今後どれかに値を挿入すると、既存ファイルの意味が静かに変わる
- OSC 引数の変換器が同じ(`{"type":"int32","value":1}` 形式)
- プロパティ名の付け方(キャメルケース)が同じ

拡張子も v1・v2・v3 すべて `json` で、v3 のファイル選択ダイアログの絞り込みも `*.json` です。
ダイアログから v1 のファイルがそのまま見えて選べます。

## 開いたときに起きること(異常ではない)

- **キューリストの時刻がファイルの値と違って見えることがある。** v3 はトリガーオフセットを適用した
  実効発火時刻を一覧に出す。トリガー時間 `01:03:20;00` にオフセット `+1 秒` が付いていれば `01:03:21;00` と表示される。
- **入力デバイスが未接続になることがある。** プロジェクトにはデバイス ID が保存されており、
  その ID の機材が今の環境に無ければ選べない。別の現場のファイルを開いたときは入力デバイスを選び直す。
  これは v1・v2 でも同じ。

## 確かめていないこと

v3 で保存し直したファイルを v1 が読めるか(逆方向)は確認していません。利用者の判断で対象外としました。
